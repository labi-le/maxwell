# 2026-10-08 — Альбомы, безопасные причины ошибок и кэш Telegram
- Решение: группировать соседние совместимые медиа с сохранением порядка по 2–10 элементов (фото/видео вместе, аудио и документы только однородно; одиночные отдельно); кэшировать только полную подтверждённую доставку с пригодными `file_id` для точной принятой нормализованной ссылки с query, того же чата и токена бота на 24 часа от свежего сохранения, без продления попаданиями; сообщать конкретную подтверждённую безопасную причину либо честно неизвестную ([альбомы](https://core.telegram.org/bots/api#sendmediagroup), [file_id](https://core.telegram.org/bots/api#sending-files)).
- Почему: сохранять публикацию и избегать повторной загрузки без дубликатов; у каждого элемента сохраняются описание по [ADR 003](003-source-post-media-captions.md), текущее экранированное имя в коде и исходная ссылка, тихая отправка и ограничения интерфейса по [ADR 005](005-silent-nonmention-replies.md); последняя существенная причина берётся из событий, исходная ошибка авторизации остаётся в родительском журнале по [ADR 002](002-on-demand-cookie-refresh.md).
- Отвергнуто: повтор альбома одиночными файлами, перезапуск после частичной/неопределённой доставки или 429, кэш неполных результатов/без идентификаторов, общий кэш между чатами/токенами, продление срока при чтении, хранение байтов медиа или URL/query/токена открытым текстом в ключе, публикация сырого stderr/ответов API/диагностических URL и догадки о причине ошибки.
- Следствия: SQLite хранит не более 200 новейших публикаций глобально, хеш ключа и упорядоченные фактические типы/`file_id`/исходные описания до 1024 UTF-16 единиц; очистка просроченного ленивая, удалённый/изменённый пост может оставаться доступен со старым описанием до истечения срока. Только однозначно неверный ID при нулевой доставке допускает сброс и одну свежую загрузку; отказ удаления сообщения не мешает кэшу полной доставки. Авторизация, доверие к группам, cookies, команды и лимиты неизменны. Откат: восстановить исходники из `target/maksut-rollbacks/albums-errors-cache-2026-10-08` и прежний образ, сохранив volume SQLite, `.env` и cookies; старый образ игнорирует новую таблицу `media_cache`.
