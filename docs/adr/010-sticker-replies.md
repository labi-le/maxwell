# 2026-10-28 — Стикер-ответы на «да» и «нет»

- Решение: таблица «слово → стикер» из пака «я устал это искать»: `да` — «Пизда», `нет` — «Пидора ответ», `ну` — «Баранки гну», `300`/`триста` — «Отсоси у тракториста», `молодец`/`молодца`/`молодцом`/`молодцы`/`молодчина` — «Молодцы, сосут концы», основы `груст*`, `депрес*`, `депрешн*`, `печал*`, `тоска`/`тосклив*`, `хандра`, `расстро*`, `подавлен*`, `поник*` — «Грустно везде». Ответ — тихий реплай. Совпадение ищется по границам слова, поэтому `нету`, `дата`, `1300` и `3000` не срабатывают, а `300$` и `300 баксов` срабатывают; из нескольких слов берётся первое. Стикеры сопоставляются по стабильному `file_unique_id`, `file_id` разрешается при старте через `getStickerSet`.
- Почему: пользователь попросил именно такую реакцию; сравнение по `file_unique_id` переживает переупорядочивание пака, а поиск по целым словам не ловит случайные вхождения.
- Отвергнуто: регулярные выражения с подстрокой (ложные срабатывания), жёстко прописанные `file_id` (зависят от бота и пакета), реакция на сообщения со ссылками (реплай остался бы на удалённом исходнике), ответы в выключенных группах и чужих личных чатах.
- Следствия: при недоступном паке стикер-ответы отключаются, остальная работа бота не меняется; стикер отправляется при `disable_notification=true`, текста и упоминаний нет.

- Уточнение: `да` и `нет` реагируют только в коротких сообщениях — не больше трёх слов, включая сам триггер, а `ну` — только когда сообщение состоит из одного слова. В длинных фразах («сначала нет, потом да») стикера нет; остальные триггеры по-прежнему ищутся в любом месте текста.
