# 2026-10-02 — Описание публикации в подписях медиа

- Решение: для каждого отправленного файла писать доступный текст исходной публикации, затем на отдельных строках кликабельное «От @username» (Telegram-профиль отправителя по ID; без username — его отображаемое имя) и прежнюю «Ссылка». Текст и имя экранируются для HTML, текст сокращается под лимит Telegram 1024 UTF-16 единицы вместе с разметкой и ссылками; если текста нет, первой строки нет.
- Почему: прежняя подпись содержала только автора сообщения и ссылку, теряя написанное автором публикации. Описание фото берётся из уже запрошенных метаданных Instagram/Pinterest/TikTok и ответа helper X; описание завершённого видео `yt-dlp` печатает на этапе `after_move` вместе с локальным путём, чтобы не делать второй запрос к сайту и не смешивать ролики плейлиста.
- Отвергнуто: повторно запрашивать метаданные всех видеороликов; сохранять полный info JSON (там могут быть подписанные URL и приватные поля); угадывать наличие видео по обложке. Для Instagram-поста `/p/DdwhVt0RuIq/` текущий экстрактор вернул ноль видеоформатов и доступные фото-превью, а публичная страница помечена как изображение: бот не может создать видеопоток из обложки.
- Следствия: если сайт не даёт описания, остаются две ссылки без пустой строки; длинное описание теряет хвост, но ссылки и корректная HTML-разметка сохраняются. Вывод `yt-dlp` читается с ограничением на отдельную запись и дренируется до EOF; содержимое описаний не пишется в журнал ошибок. Доступность видео зависит от реальных форматов сайта и cookies, а не от текста или картинки поста.
